# 协议版本与兼容规则（D4）

- 状态：冻结草案（待评审）
- 日期：2026-11-13
- 配套：docs/phase1-protocol-v0.1.md（D1）、protocol/errors.md

## 1. 版本号格式

`主版本.次版本`，当前 `0.1`。

## 2. 校验时机与行为

- 校验点：`plugin.register`（每条连接的注册帧）。
- 主版本不匹配：返回 `PROTOCOL_VERSION_MISMATCH`，Hub 关闭连接。
- 次版本不同：Hub 接受注册，记录版本号（v0.1 仅记录，不实现降级逻辑）。
- 帧顶层 `protocol_version` 与 register params 内副本不一致 → `-32602` 拒绝注册。

## 3. 兼容性判据

| 变更类型 | 版本动作 |
|---|---|
| 删除字段 | 主版本（不兼容） |
| 修改字段语义 | 主版本（不兼容） |
| 可选变必填 | 主版本（不兼容） |
| 新增可选字段/方法 | 次版本（兼容） |
| 新增枚举值 | 次版本（兼容） |
| 错误码新增 | 次版本（兼容） |
| 未知字段 | 忽略，不做版本动作 |
| 未知枚举值 | 按"能力未声明"语义处理 |

规则：兼容判定以"老插件能否不改代码继续工作"为准。

## 4. 未知字段与未知枚举值

- 插件收到含未知字段的消息：忽略未知字段，按已知字段处理。
- Hub 收到含未知字段的帧：忽略未知字段，正常处理。
- Hub 遇到未知枚举值：按"能力未声明"语义处理，不崩溃。

## 5. schema/类型同步要求

- 任何协议变更必须三同步：schema（D2）+ TS 类型（D3）+ 版本号，一个提交完成。
- 变更提案必须包含：证据（真实 Agent、真实场景）、变更内容、版本动作、三同步清单。

## 6. 冻结声明

- v0.1 冻结后，任何字段/方法/枚举变更一律走第 5 节流程，走次版本或主版本。
- 本文档与 D1 一同评审，评审通过即冻结。
